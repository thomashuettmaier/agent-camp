| #   | Topic            | Decision                                                                                                                    | Why                                                                                                                         |

## Server (apps/server)

| #   | Topic                 | Decision | Why |
| --- | --------------------- | -------- | --- |
| S1  | Layering              | Pure `core/` (diff, hub, stats, genui, store, app) + thin adapters: `office.ts` (DO) and `dev/bun-server.ts` (Bun.serve + bun:sqlite) | Same logic in unit tests, wrangler dev and the Bun harness; the DO has no business logic. |
| S2  | Hub time model        | Hub never sets timers; every call takes `now`, `nextDeadline()` drives one DO alarm (only moved earlier; an early alarm just ticks and re-arms) | Deterministic tests, and alarms fire ~once per minute instead of per heartbeat. |
| S3  | Event order           | Per diff: session.ended → person.left → person.joined (with `sessions: []`) → avatar.updated → session.started → activityChanged → subagent.* | Viewers can apply events in order without special cases; joins animate first, then desks fill. |
| S4  | New session counts    | A session that appears with subagents > 0 carries the count in `session.started`; no `subagent.spawned` for it (same for ended sessions) | One event per unit *change* of an existing session; avoids puff storms on reconnect. |
| S5  | Socket close w/o bye  | Connector stays (sessions keep showing) until its 3 min liveness timeout; after 45 s without a message (one missed 30 s heartbeat + slack) its sessions carry `offline: true` (`session.connectionChanged`, not in history) and render faded with screens off; `bye` ends sessions immediately | Deploys/network blips close sockets; connectors reconnect within seconds, so no flicker. |
| S6  | Restart / hibernation | Structural state (connectors, sessions, people) persisted as one kv row only when its fingerprint changes; socket bindings live in `serializeAttachment`; restore gives connectors a fresh liveness window | Wakes and redeploys emit no spurious leave/join; heartbeats and activity changes cause zero storage writes. |
| S7  | Takeover              | Hello with a known clientId on a new socket rebinds it; messages on the old socket get close 1000 "superseded" | Handles half-open sockets after laptop sleep. |
| S8  | History rows          | One row per viewer event except `session.activityChanged`; `person` = personId; ended/subagent rows carry agent/project from the previous state | Stats never need activity; skipping it keeps SQLite row writes far below the free 100k/day. |
| S9  | Stats                 | Heatmap weekday (0 = Mon) × hour in `OFFICE_TIMEZONE`; "most parallel" = per-person sweep of started/ended rows (clamped at 0, reset on person.left); top 5 per board; shape in `@agent-office/protocol` `StatsResponse` | Cheap to compute on request from a few thousand rows; shared type for the web page. |
| S10 | GenUI providers       | `off` (seeded), `anthropic` (raw fetch to Messages API with structured outputs, `output_config.format` = the sanitized AvatarSpec + CharacterLook JSON schema, model `GENUI_MODEL` or `claude-haiku-4-5`; see LK6, was a forced `set_avatar` tool with the catalog), `jev` = Vercel AI Gateway OpenAI-compatible `/v1/chat/completions` with `response_format: json_schema` strict, same schema (`AI_GATEWAY_API_KEY`, default model `openai/gpt-4o-mini`) | Keeps "jev" dependency-free: we use the gateway directly instead of the `typesafe-ai/jev` library; any gateway model id works via GENUI_MODEL. |
| S12 | Viewer gate         | Every route except `/ws/connector`, `/healthz`, `/install.sh`, `/login`, fonts and icons needs a session cookie (HMAC of the expiry keyed by CONNECTOR_PASSWORD, 30 days, HttpOnly, SameSite=Lax), `Authorization: Bearer <password>` (tools) or the legacy `?key=VIEWER_KEY`; pages redirect to `/login`, the rest gets 401. `run_worker_first = true` so static assets are gated too | One password to share; changing it logs everyone out; no user table. |
| S13 | Pokes                 | `POST /api/interact` (wave, coffee, cheer, message ≤ 80 chars, paper ball, tomato, send a cat, pet/feed/yarn/laser for the cats, F34–F36): broadcast to viewers as `interaction.happened`; wave/coffee/cheer/message/cat also go to the person's heartbeating connectors as `connector.poked`, shown with `osascript display notification` (text passed as argv). Limits: 1 per viewer IP / 2 s, 1 notification per person / 10 s on the server, 1 per 5 s on the connector; `notifications = false` turns them off | Fun with a hard ceiling on annoyance; old connectors ignore the unknown message. |
| S14 | Context share         | Connector sends `context` (0..1, rounded to 5% so it changes every few turns, not every turn): Claude = input + cache read/write tokens of the last main-thread request / window (200k, or 1M once past 200k or a `[1m]` model; the window isn't in the transcript); Codex = `last_token_usage.input_tokens / model_context_window` from `token_count` events; Pi: not yet. Viewers get `session.contextChanged` (not in history). ≥ 50% smokes, ≥ 80% burns, agent card shows a bar | A number, no content; makes "this session should /compact" visible from across the room. |
| S15 | Whiteboard + version  | The snapshot carries `today` (started, peak, 8 × 5-min samples, from the last 3 days of history in the office time zone) and `version` (SERVER_VERSION, else the newest connector release); the page shows `v…` next to the office name and its own build commit in the tooltip | A deploy or reload no longer resets the whiteboard. |
| S16 | Wall of shame         | Hub feeds every commit's events to `ShameTracker`: a `/clear` = session.ended then session.started of the same person within 10 s, longest wait = waiting → anything else (running waits count up to now), fire = context crossing 80%; one kv row `shame.<YYYY-MM-DD>` per office-local day (written only when a number changes) plus one `shame.waiting` row with the waits still running, so they survive hibernation and deploys; `/api/stats` adds today's top 5 of each; `/stats` shows WANTED posters | Teasing needs no new history rows; a day's row is tiny and survives restarts. |
| S17 | Birthdays             | Opt-in `birthday = "MM-DD"` in the connector config, sent in hello; viewers only ever get `birthday: true` on the day (office time zone) via `person.birthdayChanged` | A cake drone without storing or showing a date. |
| S18 | Wall-screen overview  | `?kiosk=1&view=overview`: auto-pilot fits the whole office; every `&every=` s (default 120, min 20) a 12 s close-up of the hot spot (score: waiting 10, busy 3, +helpers, +5 if burning) then back; events still get their 9 s look and return to the overview | Big screens show everything; small iPads keep the zoomed tour. |
| S11 | GenUI caching/cap     | Avatar cached per person in SQLite under key `L1:hash(personId+description)` (person-level since M1; `L1` look revision and no provider name since LK8); job only when that key changes (join with new description); no description = no AI call (LK7); daily counter `genui.calls.<UTC date>`; failures/cap/unusable output keep the previous look (else the seeded one) under `key:fallback` so the next join retries (LK9); cap default 50 (was 200, LK15) | Near-zero cost, bounded, and a transient error doesn't pin a person to the seeded look forever. |
| S12 | Password              | `CONNECTOR_PASSWORD` secret; unset → every connector rejected (4001) unless `DEV_MODE=1` (then "devpass"); `bun run dev` copies `.dev.vars.example` → `.dev.vars` | Safe default in prod, zero-setup locally. |
| S13 | Snapshots             | PNG magic check, ≤ 300 KB, stored as BLOB in DO SQLite, 1 upload / 10 min server-side (429 + Retry-After); `Authorization: Bearer <CONNECTOR_PASSWORD>` bypasses the limit (simulator/screenshots); empty-office skipping is the recorder's job | A week of 15-min frames at ~50–150 KB fits easily in DO storage; no R2 needed. |
| S14 | install.sh            | Bundled into the Worker as a wrangler `Text` module from `apps/connector/install.sh`; the literal `__AGENT_OFFICE_SERVER__` is replaced with the request origin | One-liner install works from whatever host serves it, no hard-coded URL. |
| S15 | Static assets         | `[assets]` from `../web/dist`, `run_worker_first` for /ws/*, /api/*, /healthz, /install.sh; default `auto-trailing-slash` maps /stats → stats.html | Assets are served without invoking the Worker (free, not counted as requests). |
| S16 | Extra protocol fields | Additive: `office.snapshot.data.timezone?` (day/night) and `packages/protocol/src/api.ts` (`HistoryRow`, `StatsResponse`, `SnapshotList`) | Web and simulator share the HTTP shapes with the server. |
| S17 | Request budget        | Estimate for 10 connectors, 10 h/day: heartbeats 10 × 1,200 = 12k msgs + ~20k change snapshots = ~32k incoming WS msgs ÷ 20 ≈ 1.6k billed requests; alarms ≈ 600–800; WS upgrades, viewer connects, /api calls and 40–96 snapshot posts ≈ 300–500 → **≈ 2.5–3.5k requests/day** (≈ 4–5k if laptops stay on 24 h). Ping/pong auto-responses are free; outgoing broadcasts are not billed; static assets are free | Comfortably within "a few thousand/day" on the shared 100k free plan. |

## Connector (apps/connector)

| #   | Topic                 | Decision | Why |
| --- | --------------------- | -------- | --- |
| C1  | Runtime deps          | Zero beyond `@agent-office/protocol` (Bun WebSocket/fetch/crypto/spawn, hand-rolled flat TOML) | Smallest binary surface; nothing to audit or break on cross-compile. |
| C2  | Process detection     | `ps -axo pid=,ppid=,ucomm=,args=` on macOS (one spawn), `/proc/*/cmdline` + `/proc/*/stat` on Linux; match the executable's file name (`ucomm`, cut by its fixed 16-char width), else argv0 or `node/bun <script>`, against claude/codex/pi. `ucomm` is what finds Claude Code run by the Claude desktop app: its path (`~/Library/Application Support/Claude/claude-code/…/claude`) has a space, so the whitespace-split `args` argv0 is garbage; its `disclaimer` wrapper is not an agent. `codex app-server` (the Codex app's daemon and its `--listen` child, IDE backends) is a `daemon`: it counts as "codex runs" for fresh transcripts but owns no session by pid file or cwd (it pinned the newest transcript in its cwd as a permanent idle ghost desk), so agents below it are nobody's helpers. An agent with an agent ancestor (`hostPid`) is hosted: it never counts as running, and a session its pid file names is hidden (remembered while the transcript exists). Hosted agents except Agent SDK backends (`claude-agent-sdk` in argv), e.g. purrness subagent workers (`pi` under `pi`, nested ones too), count as helpers (robots) of the session their top-level host owns (pid file or cwd match); any live hosted process keeps that session from going idle for at most 10 min of transcript silence. A hidden session shows again once a top-level pid's pid file owns it (`claude --resume <id>`). A same-kind native child of a JS launcher (npm Codex: `node …/bin/codex` → `vendor/…/codex`) is the launcher's own binary, not hosted | Claude/Pi often run as `node …/cli.js` and the native Claude binary's file name is its version number. Pi's Claude bridge runs the Agent SDK `claude` binary as a child with its own pid file and transcript, which showed every bridged Pi session twice. |
| C3  | Liveness              | Live = Claude pid file with a running claude pid, OR newest transcript whose folder/cwd matches a running agent's cwd (lsof, cached per pid), OR transcript < 90 s old while any process of that agent runs; the first two stay live as `idle` | Pid files/cwd give exact process ties and real idle; the mtime rule keeps it working without either. |
| C4  | Test mode             | `--assume-processes` / `AGENT_OFFICE_ASSUME_PROCESSES=1` = every agent running and every pid-file pid alive; `--home`/`AGENT_OFFICE_HOME` replaces ~ and then ignores CLAUDE_CONFIG_DIR/CODEX_HOME/PI_CODING_AGENT_DIR | Fixtures run on Linux CI; a fixture run can never pick up the real ~/.claude via a stray env var. |
| C5  | Activity extras       | Assistant text with no end marker + 30 s silence → `waiting`; "[Request interrupted by user" / Codex task_complete/turn_aborted / Pi aborted → `waiting`; question tools (AskUserQuestion, request_user_input, purrness_ask_question, also MCP-prefixed; a bare `ask_question` is not, e.g. `mcp__deepwiki__ask_question`) → `waiting`; TodoWrite/Task/MCP tools → `thinking`; subagent count forced to 0 when idle | Not every agent version writes stop reasons; idle desks shouldn't show busy helpers. |
| C6  | Session key           | `sha256(clientId:agent:rawId)` → 16 hex chars | Salted per laptop so keys can't be joined across machines or reversed to session ids. |
| C7  | Codex scan scope      | Only the two newest `sessions/YYYY/MM/DD` folders | Constant cost per poll, independent of the date; a resumed week-old rollout is missed (acceptable). |
| C8  | Claude cwd fallback   | Pid file cwd → transcript `cwd` field → greedy filesystem-guided decode of the folder name; `agent-*.jsonl` next to sessions ignored | Basename is right even for hyphenated folder names; legacy sidechains aren't separate sessions. |
| C9  | Self-update safety    | Download → temp file next to the binary → run `<tmp> version` → require strictly newer → atomic rename → exit(0) (launchd KeepAlive restarts); failed version not retried for 10 min; dev builds and `bun src/main.ts` never update; `AGENT_OFFICE_NO_UPDATE=1` disables | A broken or stale (CDN-cached) asset can never replace a working binary or cause a restart loop. |
| C10 | GitHub poll           | Every 5 min: REST `releases/latest` tag_name, falling back to the `/releases/latest` redirect `Location` | Unauthenticated API is 60 req/h per IP; ~10 laptops on one office NAT would exceed it. |
| C11 | Below min version     | Stay connected but send no snapshots until the update succeeds | PLAN: "update before sending anything else"; the server would reject the old shape anyway. |
| C12 | Bad password (4001)   | Retry after 5 min, no exponential hammering; 4002 → update then normal backoff | A typo shouldn't flood the server; too-old fixes itself. |
| C13 | Config/status         | `configure` subcommand writes the TOML (0600, atomic) so install.sh never quotes TOML; daemon writes `status.json` each poll, `status` treats it as stale after 10 s or a dead pid | Shell quoting bugs avoided; `status` works without IPC. |
| C14 | install.sh            | POSIX sh, prompts via /dev/tty (stdin is the curl pipe), env `AO_*` for non-interactive, accepts both `__AGENT_OFFICE_SERVER__` (what the server substitutes) and `__SERVER_URL__` placeholders, installs to ~/.local/bin, Rosetta-aware arch detection | Works as `curl … | sh`, in CI, and with either placeholder convention. |
| C15 | launchd               | `~/Library/LaunchAgents/dev.agentoffice.connector.plist`, RunAtLoad + KeepAlive + ThrottleInterval 5, stdout/err → `~/Library/Logs/agent-office.log`, `launchctl bootout` then `bootstrap gui/<uid>` | Re-running the installer is idempotent; exit(0) after an update restarts within ~5 s. |
| C16 | Linux                 | Builds and runs (for tests); no service manager integration, logs to stdout | Team is macOS-only. |
| C17 | Cowork sessions       | Opt-in `cowork = true` (default off). While the Claude desktop app runs (`…/Claude.app/Contents/MacOS/Claude` in the same `ps` output), scan `~/Library/Application Support/Claude/local-agent-mode-sessions/<account>/<org>/[agent/]local_*/.claude/projects/*/*.jsonl` with the Claude normalizer. Live = transcript written < 30 min ago (`COWORK_LIVE_MS`) and the app running. Pid files in those folders are ignored. Agent `claude`, project fixed to "Cowork". Folders are walked every 30 s; in between only transcripts that were recent at the last walk are re-stat'ed. `ClaudeDesign` counts as a typing tool | Opt-in because Cowork is often not coding work and connectors auto-update, so it would otherwise appear for everyone at once (review of PR #23). Cowork can run inside the app's VM, so no process on the Mac owns a session and the pid files hold VM pids that could match unrelated processes. The cwd is `…/outputs` or `/sessions/<random>`, useless as a project name, and session titles are content. 30 min keeps the desk from coming and going between prompts. Finished sessions pile up, so a full walk every 2 s would grow without bound. Checked live on Claude app 4.23118.0: current Cowork chats (`claude.ai/cowork/cse_…`) run in the app VM (`vm_bundles/claudevm.bundle`) and write no transcript on the Mac, so only older sessions are found. |
| C18 | Claude Design desk    | Declared, not detected: opt-in `claude_app = "design"` (macOS; `configure --claude-app design` or `off`). While the Claude app runs (same `ps` output as C17) the person has exactly one session of the agent kind `design`, raw id `claude-app`: `thinking` while the Claude app is the frontmost app, `idle` after 2 min in the background, gone when the app quits. Frontmost app = `lsappinfo front` + `lsappinfo info -only bundleid <ASN>` (ships with macOS, no permission), every 5 s while the app runs, 2 s timeout. A failed query changes nothing (the desk only drifts to idle). With it on, Cowork sessions (C17) are not shown, so the person is one desk | Claude Design runs in Anthropic's cloud inside the Claude app's main window (checked live on app 4.23118.0): no transcript, no process, no separate window, and window and page titles don't change. The one local signal that worked, the `claude.ai/code/artifact/…` page address in the app's accessibility tree, needs `AXManualAccessibility`, which switches the user's Claude app into full accessibility mode until it restarts and depends on claude.ai routes; rejected in review (#32). Declaring it changes nothing in the Claude app and needs no permission. The cost: the desk does not know whether the person is designing or chatting in the app, which is fine for someone who declared that the app is their design tool. |
| C19 | Design: what leaves   | Only agent kind, hashed key, activity and start time; no project. Locally the connector learns only the frontmost app's bundle id, nothing about the Claude app's windows or content | Same privacy rule as transcripts; covered by the privacy test. |

### Connector: unbuilt

- Claude Design activity (is Claude generating?) is not shown. Routes looked at and dropped: polling Anthropic's Design MCP endpoint (`api.anthropic.com/v1/design/mcp`, lists project files with change stamps) would need the person's Claude login token, and Anthropic's terms forbid tools from collecting or using Claude.ai credentials; the app blocks `remote-debugging-port`; its logs have no Design entries. Unexplored: the Design page writes chat drafts to the app's Local Storage (`omelette.chatDraft.<project>.<chat>`), which could show "is writing a prompt".
- Claude Design desk: checked live (`lsappinfo` answers without any permission). Not checked: whether `lsappinfo` behaves the same on every macOS version the team runs.

- Optional Claude Code hook (`~/.claude/settings.json` pinging the daemon on session start/end) is not built; 2 s file polling is fast enough.
- launchd/`install-service`/`uninstall` and the darwin binaries are untested on a real Mac (cross-compiled from Linux; arm64 binary carries an ad-hoc LC_CODE_SIGNATURE).

## Simulator (tools/sim)

| #    | Topic              | Decision | Why |
| ---- | ------------------ | -------- | --- |
| SIM1 | Script model       | Scenarios are generators of `Step`s (`connect/bye/drop/reconnect/start/end/activity/subagents/wait/settled`) over a pure `World`, driven by `seededRandom("sim:<scenario>:<seed>")`; the runner applies each action before pulling the next | Same seed = same script; `dryRun()` replays it on a virtual clock with no network, so determinism and schema validity are unit-tested. |

## Turn-based games (protocol games/, server core/games.ts, web ui/gamesUi.ts)

| #   | Topic | Decision | Why |
| --- | ----- | -------- | --- |
| G1  | Pure rules in the protocol package | `packages/protocol/src/games/`: one `TurnGame` interface (`setup`, `phase`, `turn`, `awaits`, `apply`, `outcome`, `view`) with plain JSON states and no I/O, clock or unseeded randomness. `apply` returns a new state plus events, or the reason a move is illegal. | The server (which will own the state), the page (legal moves, previews) and the tests share one set of rules, and the state can be stored as it is. |
| G2  | Battleship is the short salvo variant | 8x8, fleet 4-3-3-2, ships may not touch (corners count), a salvo of 3 shots per turn with the results together, no extra shot on a hit; the cells around a sunk ship are known water and no longer targets; the last salvo shrinks to the cells left. Simulated with both sides hunting sensibly: 10 to 13 turns per side (classic 10x10 with shoot-again: 18 to 32) | Played asynchronously, a turn is a handoff between two people. The classic game needs 50 to 70 of them, and an 8x8 board still has finger-sized cells on a phone. |
| G3  | The first mover opens with 2 shots | `BATTLESHIP_FIRST_SALVO = 2` for the opening turn of the side that moves first | With 3, the first mover won 59.5% of simulated games between equal players; with 2 it is 53.4% (with 1 it flips to 45.5%; a "last reply" rule gives 20% draws). |
| G4  | Hidden information goes through `view()` | A fleet is in a view only for its owner, plus the ships that were sunk; when the game is over both fleets are shown. A test plays 500 random games and checks every view after every turn | Everything a browser gets must come from `view()`, so a spectator or the opponent can never read a fleet out of a message. |
| G5  | Four in a Row | 7x6, `drop` a disc in a column, four or more in any direction wins and the line is reported, a full board is a draw; nothing hidden, so the view is the state. `setup({ first })` lets the caller decide who starts (e.g. the loser of the last game) | A second game with no hidden information and about 15 moves per side. |
| G6  | Games on the server | `apps/server/src/core/games.ts`, all games in one KV value `games.v1` (like the party points): an office has a handful at a time, and no table or migration is needed. `POST /api/games` (challenge, accept, decline, cancel, move, resign, nudge, claim, call-off, seen, notices) needs the `ao_me` cookie and acts as that person; `GET /api/games/:id` returns the board as the asker may see it. Viewers get `game.updated` and the snapshot's `games`, both built from the engine's spectator view, so a fleet leaves the server only in the answer to its owner. Limits: 3 open games per person, one per pair and kind, a burst of 5 requests per second per address and claimed person (a move and the page's "seen" arrive together, and an office shares one address) | Hidden information needs the one "me" from L12, and the smallest storage that survives a restart. |
| G7  | Deadlines without a clock that beats you | A move has three days of weekday time (Saturdays and Sundays in `OFFICE_TIMEZONE` do not count). Then nothing happens by itself: the waiting player may claim the win, call it off or keep waiting. An unanswered invite runs out after the same time, a game untouched for 14 days ends without a result. A nudge is possible after 4 hours of weekday time, once a day per game. Expiry and notices ride on the existing alarm (`games.nextDeadline()`), so they do not depend on somebody opening the game | An automatic loss after 48 h would punish weekends, sick days and holidays in a workplace toy. |
| G8  | Records and ratings | Wins, losses and draws for every finished game (won, gave up, claimed, draw); Elo (K=24, start 1000, "?" for the first five) only for games the challenger marked rated, which the invite says. The loser of the last game of a kind starts the next; otherwise the challenged person. The drawer shows the top five and your own row; the kiosk shows no ladder | With about ten people a full ranking is mostly noise and puts somebody at the bottom. |
| G9  | Mac notices | `connector.poked` from "Office games", no connector change. A notice waits 60 s; a page that is visible and confirmed as that player answers `seen` once per change, and then nothing is sent. At most one per person per 30 min, several bundled ("3 games are waiting for you"), a per-person switch (`notices`), no queue for a Mac that is offline. A notice waits while a "this is me" code is pending for that person, and a code asked for within 5 s of a notice gets a 429 with the reason: the connector drops a notification within 5 s of the previous one, and a swallowed code would look like a broken login | Somebody looking at the office needs no notification, and nobody wants 20 a day. |
| G10 | Boards in the page | `ui/gamesUi.ts` + `ui/gameBoard.ts`. A fullscreen window (Esc closes, the focus stays inside and returns to where it was). Battleship grids are ARIA grids: one tab stop, arrow keys, Home/End, a typed coordinate moves the focus; a cell is a button named "C4, hit"; states have a glyph besides the colour (○ miss, ✕ hit, hatched sunk, · known water, brackets for the latest salvo). Placement needs no dragging: pick a ship, pick a cell, Rotate (R), Shuffle. A salvo is picked and then fired, which is also the protection against a mis-tap. Four in a Row is seven column buttons (digits jump to a column); on touch the first tap shows the landing cell. Phones show one grid at a time. A status line (`role="status"`) says what the other side did, one sentence per turn. Not built: projectiles between characters, a games demo mode, voiding a game when a player leaves the office | The parts most likely to be unusable without a mouse or on a phone. |
| G11 | Party moves need "me" on the server too | `POST /api/party` returns 403 unless the request carries the `ao_me` cookie of its `personId`. L12 kept this to the page | One "me" everywhere; with games bound to the cookie an open party endpoint would be the odd one out. |
